# Bring-up por gates

Todos los gates empiezan PENDING_PHYSICAL_VALIDATION. Usar [BOM mínimo](../sortv1/hardware/bom/bom_mvp_minimum.csv), [wire-from/to](../sortv1/hardware/wiring/wire_from_to.csv), [pinout](../sortv1/hardware/pinout/pico.csv), [árbol](../sortv1/hardware/electrical/power_tree.md) y [cadena](../sortv1/hardware/electrical/safety_chain.md). TBC_MODEL requiere seleccionar datasheet/pins/rating; TBC_MEASURE requiere instrumento/evidencia; TBC_CALIBRATE requiere parámetros reales. No energizar una conexión histórica solo por aparecer en el gemelo.

Las fases3/4 permiten preparación eléctrica/mecánica sin movimiento; no se puentean guardas para adelantar giro. Completar lecturas/calibraciones5–8 y volver al banco si son prerrequisitos. HIL de protocolo no energiza motores. Una masa patrón y movimiento manual sin energía sirven para calibrar sin reenviar comandos STEP/PWM desde Pi.

Firmware: copiar calibration.json a archivo de mediciones, completar active_high[29], tare/escala/presencia/span, servo endpoints, periodo STEP/dirección y cuatro full/hysteresis; status=CALIBRATED, operator y evidence_path real. `python scripts/configure_firmware.py --calibration RUTA --output sortv1/firmware/include/calibration.hpp` desde raíz; compilar, registrar hash, flashear con BOOTSEL/energía aislada. Header seguro por defecto queda verified=false. No usar valores de otro mecanismo como medición propia.

Camera: `python -m app.tools.calibrate_camera --help` desde sortv1. Todos los argumentos son valores medidos, no defaults universales; guardar evidencia vacío/objeto nítido/desenfoque/exposición y P08/P09. Para dataset usar capture_dataset y objetos independientes por split.

Avanzar solo con firma/evidencia por gate; cualquier STOP devuelve a energía aislada y [RECOVERY](RECOVERY.md). P01–P16 no se completan desde CI/smoke/simulación. El reflector de llenado es orientativo; revisar recipientes y no usarlos como certificado de capacidad exacta.
