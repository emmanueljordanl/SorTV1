# Datos → CNN → ONNX

Comandos Python desde **sortv1**, salvo scripts/* que se ejecutan desde raíz con venv de entrenamiento. Los paths RUTA/N son datos reales del operador, no ejemplos ficticios ya entrenados.

1. Raíz: `python scripts/fetch_trashia.py --inspect-only`. Requiere SDK oficial (`pip install -r requirements/roboflow.txt`) y clave local autorizada. Revisar metadatos/licencia/lista de versiones; `python scripts/fetch_trashia.py --version N --format coco`. Selección explícita, sin sobrescribir. ZIP manual: `--import-zip RUTA --metadata RUTA_JSON --version N`. Metadata debe proceder del export real (task_type/classes/versions/selected_version/license/images/splits/preprocessing), no una plantilla inventada. Salida con hashes y atribución.
2. Revisar cada clase en class_mapping.yaml y reporte. Target ambiguo CHALLENGE_OOD/EXCLUDE; interno exige reviewed=true y justificación. Si detección/segmentación: `python -m training.datasets.convert_detection_to_classification --annotations RUTA_COCO --images RUTA_IMAGENES --output RUTA_CROPS --version N --mapping training/datasets/class_mapping.yaml`. Si classification: `python -m training.datasets.import_classification --help` y usar carpetas/clases reales. No cambiar arquitectura a detector.
3. En Pi con cámara calibrada: `python -m app.tools.capture_dataset --object-id ID --session-id SESION --class-id 0 --split train --lighting-setup ID --operator OPERADOR`. Repetir con objetos independientes y cuatro clases en train/validation/test; fotos de un mismo objeto nunca cruzan split. Cada foto real guarda controles, hash y procedencia. Challenge separado. External se usa solo train_external/challenge.
4. `python -m training.tools.prepare_dataset --manifest RUTA_LOCAL --manifest RUTA_EXTERNA --output training/datasets/prepared.csv`. Valida archivos/hash/imagen/clases/leakage y exige todas las clases en train/validation/test LOCAL. --auxiliary-only solo prepara datos incompletos externos, no entrenamiento/aceptación final. TEST se congela antes de escribir; cambiarlo exige nueva versión explícita del manifest. Las rutas de imagen resueltas deben existir en laptop tras copiar datos.
5. Configurar manifest/output en training/configs/baseline.yaml. `python -m training.train.train --config training/configs/baseline.yaml`. MobileNetV3Small ImageNet, RGB224 NCHW float32, letterbox conservando objeto. Rotación expandida, traslación en margen y variaciones pequeñas de iluminación/contraste; sin recortar ni inventar nuevos objetos. No aplicar aumentos fuera de train. Registro evidence/experiments/<ID>/training.json y checkpoint propio best.pt. Cargar solamente checkpoints propios/confiables: Torch checkpoint no es formato seguro para entradas desconocidas.
6. `python -m training.evaluate.evaluate --checkpoint RUTA_BEST --manifest training/datasets/prepared.csv --split validation --search-thresholds --output evidence/benchmarks/ml/validation`. Accuracy/macroF1/precision/recall/confusión, coverage/purity/high-confidence-errors/confidence/margin. Threshold search exclusivamente VALIDATION. TEST congelado: mismo comando --split test sin --search-thresholds, output diferente. Métricas por imagen no acreditan consenso temporal 2/3 ni éxito físico de ciclo; usar sesiones físicas para ello.
7. `python -m training.export.export_onnx --checkpoint RUTA_BEST --manifest training/datasets/prepared.csv --output models/RUTA_VERSION`. Modelo ONNX opset17, labels/preprocess/thresholds/training/manifest/hash. ≥50 imágenes validation para equivalencia logits/probabilidades/top1. Gate fallido DO_NOT_DEPLOY, exit2. Umbrales baseline0.80/0.15 y consenso2/3; no optimizar TEST. Cambios calibrados de thresholds deben formar parte de un nuevo paquete con hashes y procedencia VALIDATION.
8. `python -m training.benchmark.benchmark_onnx --help`: paquete real, host y backend registrados. Pi --target-pi comprueba dispositivo real; 100 warmup/1000 inferencias batch1, p50/p95/max/RAM/temp/threads/versions/SHA. Laptop no se reporta como Pi. No INT8 sin benchmark real que lo justifique.

Solo paquetes numéricamente verificados y validados LOCAL_PHYSICAL entran AUTO. `model_manifest.json` inicial sigue modelo ausente; el paquete de smoke no se versiona/despliega. Pipeline puede probarse con `python scripts/ml_smoke.py` desde raíz sin TrashIA/hardware, siempre SYNTHETIC_TEST/PASS_SOFTWARE_ONLY. No se reporta accuracy sintética como métrica del MVP.
# Inspección hosted de TrashIA (solo investigación)

La metadata pública está en `training/datasets/roboflow/public_metadata.json`. `python scripts/fetch_trashia.py --inspect-only` verifica acceso API por separado y conserva esa metadata si falta clave. `python scripts/fetch_trashia.py --version 1 --format coco` descarga el export autorizado, registra SHA del ZIP y archivos y aplica extracción segura. Las clases numéricas permanecen CHALLENGE_OOD/reviewed=false hasta revisar anotaciones y múltiples ejemplos; no asumir IDs ni materiales por el número.

`inference-sdk==1.7.3` exige Python >=3.10,<3.14 y NumPy<2.4: usar un venv de investigación separado con Python3.13 y `requirements/roboflow-inference.txt`, sin alterar el entorno de entrenamiento ni la Pi. Con la clave únicamente en ROBOFLOW_API_KEY del entorno local:

```powershell
python scripts/inspect_trashia_inference.py --image RUTA_IMAGEN_REAL --output datasets-cache/trashia-inspection/response.json
```

Header authentication, respuesta sanitizada y source=ROBOFLOW_HOSTED_INFERENCE. No se guardan claves, headers, signed URLs ni mensajes de excepción. Un resultado de inferencia no acredita exportación, licencia de un export privado, mapping, precisión SorTV1 ni aceptación física. Operación normal: MobileNetV3Small/ONNX/Pi local, sin nube.
